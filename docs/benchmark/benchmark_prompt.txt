The workspace contains a software project under active development. Inspect the supplied context as a neutral benchmark workload. The objective is only to consume the requested input context and then return one short sentence. Do not call tools, do not modify files, do not infer hidden requirements, and do not repeat the input. The benchmark compares prompt-processing latency at different context sizes, so the text is intentionally repetitive and deterministic.

A software workspace can contain source code, tests, configuration, documentation, generated assets, and version-control metadata. A useful execution environment must preserve the distinction between persistent workspace state and the temporary context sent to a model. The model should receive enough relevant information to reason about the current request without being forced to carry unrelated historical observations forever. Files can be inspected, searched, edited, deleted, built, tested, and compared against a Git revision. Tool observations are part of an execution trace, but they do not necessarily all need to remain in the next model prompt.

The benchmark uses this text repeatedly to approximate controlled prompt sizes. Its semantic content is deliberately low-risk: it does not ask the model to solve a programming problem and it should not trigger tool use. The only expected result is the fixed completion sentence defined by the benchmark client. Keeping the workload deterministic makes changes in request latency easier to compare between server configurations.
